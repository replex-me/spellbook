# Ordered patch series

The order and aggregate byte hash of these patches are locked by `../upstream.json`. Later patches may extend tests or implementation introduced earlier, so apply the complete series cumulatively.

Each engine change must have a native regression test for the violated invariant: one Undo boundary, exact Undo/Redo, failure rollback, object identity, master/layout preservation, or save/reopen semantics. Case-specific slide numbers, object names, coordinates and corpus identifiers are not valid production conditions.

The current `undo-v22` r9 source candidate extends the cumulative series through table API inheritance, table text-cursor Undo, exact existing-master layout selection, observable mixed-script text formatting, native object creation/duplication, metric-driven text-layout invalidation, sparse-master-safe slide insertion, bounded object interactions, slide metadata, line style, paragraph formatting, slide sections, the complete animation-effect lifecycle and document design in `0027`–`0041`. Patch `0036` moves PPTX click-action serialization to one shared shape-export boundary. Patch `0037` replaces the picture-placeholder-only URL workaround with the general OOXML inheritance rule: master and layout values are inherited first, then already parsed local non-visual properties win. Patch `0038` adds typed page, line and paragraph mutations with one native Undo boundary and PPTX reopen coverage. Patch `0039` gives section definitions one atomic Undo and PPTX round-trip boundary. Patch `0040` exposes preset-backed animation add, remove, replace and reorder without flattening the animation tree. Patch `0041` adds document-wide slide sizing plus master theme colors and major/minor font schemes, and fixes complete theme copying so format schemes are never dropped. `sourcePatchSeriesReady` records only clean application to the pinned source. `sourceCandidateReady` remains false until the single final integrated build and both declared C++ suites pass. Runtime promotion remains separate and requires the browser, OOXML, visual and PowerPoint checks described in the parent README.
